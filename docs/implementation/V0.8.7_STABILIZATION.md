# V0.8.7 Stabilization

Purpose: create a trustworthy checkpoint before the multi-business Accounting migration in Issue #28.

## Changes

- `README.md` now describes the actual V0.8.x ecosystem instead of the obsolete V0.2 PIN-only accounting app.
- `docs/CURRENT_STATE.md` is the compact fresh-agent checkpoint and points to Issue #37 as the delivery roadmap and Issue #28 as the next major implementation boundary.
- `npm test` now performs executable architecture/bootstrap tests in addition to syntax checks.
- production start commands preload `bootstrap-env.js` before any database Pool or child gateway starts.
- ambiguous PostgreSQL URL SSL modes (`prefer`, `require`, `verify-ca`) are normalized to explicit `verify-full` to preserve certificate-verifying behavior across the upcoming pg connection-string semantic change.

## Non-goals

This slice does not:
- modify financial data or accounting tables;
- create a pilot territory;
- approve/invite real participants;
- configure Google OAuth or an outbound email provider;
- implement Issue #28 multi-business accounting itself.

## Validation gate

Before merge:
1. GitHub Actions CI must pass on the exact PR head.
2. `npm test` must execute both syntax and Node test-runner checks.
3. isolated Railway preview must deploy the exact feature branch.
4. `/health` must pass through the full gateway chain.
5. runtime logs must no longer emit the pg `sslmode=require` future-semantics warning when the configured URL uses an affected mode.
6. production data is not mutated beyond existing additive startup migrations.
