# V0.8.5 Authentication Hardening

Implementation target: Issue #23 / PH Pilot Roadmap Phase 1.

## Public authentication boundary

- Normal sign-in is email + password.
- The legacy PIN UI is hidden and the public `/api/login` PIN route is retired by `server-auth-hardening.js`.
- Legacy three-part bearer sessions are rejected at the public gateway.
- The bootstrap owner may use the legacy PIN only through the one-time owner migration route, before permanent retirement.

## Recovery and verification

- Password-reset and email-verification links use cryptographically random one-time tokens.
- Only token hashes are stored in PostgreSQL.
- Password reset revokes existing sessions.
- Preview-only direct reset/verification URLs require `AUTH_PREVIEW_SHOW_LINK=true`; production must not enable this flag.
- Outbound email is optional until a provider is configured. The initial adapter supports Resend through environment-only credentials.

## Google identity

Google OAuth/OpenID Connect is feature-gated by `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.

- Provider subject (`sub`) is the durable external identity.
- A Google user with an email that already belongs to a Business & Life account is not silently merged.
- Existing users link Google only while authenticated.
- OAuth callback returns a short-lived one-time handoff code; the durable Business & Life session token is not put in the callback URL.

## Validation gate

Before merge:

1. GitHub Actions must pass on the exact PR head SHA.
2. Railway preview must build the exact PR head SHA, run `npm test`, and pass `/health`.
3. Runtime logs must show `server-auth-hardening.js` as the public entry process above the existing incident/delivery/supplier/marketplace/order/accounting chain.
4. Preview may use direct reset/verification links for testing; production may not.
5. Google is considered configured only after provider credentials and callback URI are installed and tested; absence of those credentials hides the Google button rather than weakening password auth.

No secret values belong in this file or in GitHub issues/logs.
