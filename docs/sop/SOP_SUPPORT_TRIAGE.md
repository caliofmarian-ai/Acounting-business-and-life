# SOP — Support Triage, Self-Service Guidance and Escalation

## Purpose

Resolve ordinary user problems quickly using public/private documentation while routing high-risk issues to the correct authority.

## Scope

Applies to Support handling across account, profile, order, accounting, Supplier, Delivery, Local Services and incident domains.

## Roles

- Support Agent owns first classification/self-service guidance.
- Domain owners handle privileged or specialist escalations.
- Admin handles authorization decisions only through granted authority.

## Prerequisites

- Support case/request exists.
- Agent has only the access required for assigned case.

## Inputs / evidence

- User issue description.
- Relevant IDs/statuses.
- Help code/article.
- Authorized account/order/profile data.
- Existing incident/support history.

## Procedure

1. Identify the user goal/problem before requesting additional data.
2. Use the least-sensitive information necessary to locate the issue.
3. Classify domain: account/auth, profile authorization, order/marketplace, accounting/money, Supplier, Delivery, Local Services, incident/safety, compliance/legal or technical.
4. Provide public Help Center/article guidance when self-service can safely solve the issue.
5. If private account/business context is needed, use authorized support access only.
6. Do not ask for passwords/secrets.
7. For money disputes, collect identifiers/evidence and escalate to Finance/Reconciliation rather than invent payment outcome.
8. For authorization/evidence questions, escalate to Admin/Compliance rather than promising approval.
9. For safety/fraud/privacy, create/route private Incident and escalate urgently when necessary.
10. Record case notes, actions, links provided and escalation owner.
11. Close only when resolved or correctly handed over with clear status.

## Control points

- No password/secret collection.
- No unauthorized private evidence access.
- No promise of refund/approval outside authority.
- Use contextual Help Center where appropriate.
- High-risk domains have explicit escalation.

## Prohibited shortcuts

- Resetting money/status by database manipulation to satisfy a user.
- Sharing another user's data.
- Giving unsupported legal/tax advice.
- Closing/escalating without notes.
- Using public chat for private evidence.

## Exceptions / escalation

- Immediate safety → emergency/incident route.
- Security incident → Security/Privacy.
- Regulatory/legal → Country Compliance/qualified adviser.
- Service outage → Technical/Platform Operations.

## Records / audit

- Support case.
- Notes/actions.
- Identity verification method/evidence as allowed.
- Escalation.
- Related incident/help article.
