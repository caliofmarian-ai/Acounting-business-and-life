# V0.8.1 Local Services

This implementation adds the Philippines-edition `service_provider` profile and Local Services workflow on top of the shared account/profile architecture.

Key invariants:
- one account may hold Customer, Merchant, Supplier, Courier and Service Provider profiles;
- raw CV and credential evidence are private;
- public profiles expose only public-safe fields and verification status;
- `Verified` is never displayed before platform verification;
- public reputation is opt-in;
- only completed, customer-confirmed in-app service jobs can create a verified review entitlement;
- service categories are data-driven and jurisdiction-aware.
- the Provider sees only official coarse area before Customer quote acceptance;
- exact service address is fetched intentionally only for accepted/scheduled/in-progress work, is never returned by Provider job lists or mutations, and every successful access is audited without duplicating the address;
- exact-address access expires outside the active fulfilment window.

Runtime validation is performed through GitHub Actions and the isolated Railway preview before promotion to `main`.
